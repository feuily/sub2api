
# Go Wire（wire.go）快速入门：它是干什么的，为什么要用？

你说的应该是 Go 语言中的 Google Wire 依赖注入工具（`google/wire`）。

我先用最简单的一句话解释：

Wire 就是帮你自动组装 Go 程序中各种对象的工具。

当一个项目越来越大，一个对象需要依赖另外几个对象，而另外几个对象又依赖其他对象时，Wire 可以帮你把这些东西按照正确的顺序组装起来。

它解决的不是业务逻辑问题，而是项目中越来越复杂的对象创建和依赖关系管理问题。

## 一、先理解一个最简单的例子

假设你正在开发一个 Go 后端服务，需要：

1. 一个 MySQL 数据库连接。
2. 一个 UserRepository，负责操作用户数据。
3. 一个 UserService，负责用户业务。
4. 一个 UserHandler，负责接收 HTTP 请求。

它们之间的关系是：

UserHandler

HTTP 请求处理

UserService

用户业务逻辑

UserRepository

数据库操作

MySQL DB

数据库连接

注意：上面的箭头表示依赖关系。

例如：

- UserHandler 需要 UserService。
- UserService 需要 UserRepository。
- UserRepository 需要 MySQL DB。

### 不使用 Wire，怎么写？

你需要自己创建每个对象：

```
func main() {
    // 1. 创建数据库连接
    db := NewDB()

    // 2. 创建 Repository
    userRepo := NewUserRepository(db)

    // 3. 创建 Service
    userService := NewUserService(userRepo)

    // 4. 创建 Handler
    userHandler := NewUserHandler(userService)

    // 5. 启动 HTTP 服务
    _ = userHandler
}
```

这段代码没有任何问题。

但当项目有几十个甚至几百个组件时，你可能需要手动管理大量依赖关系。

Wire 就是来解决这个问题的。

## 二、Wire 到底是怎么工作的？

你只需要先记住三个概念：

| 名称        | 通俗理解       | 实际作用                   |
| ----------- | -------------- | -------------------------- |
| Provider    | 生产零件的工厂 | 创建对象的函数             |
| Injector    | 组装工人       | 告诉 Wire 最终需要什么对象 |
| wire_gen.go | 组装好的说明书 | Wire 自动生成的 Go 代码    |

### 1. Provider：对象生产工厂

例如：

```
// 创建数据库
func NewDB() (*sql.DB, error) {
    db, err := sql.Open("mysql", "user:pass@tcp(127.0.0.1:3306)/test")
    if err != nil {
        return nil, err
    }

    return db, nil
}

// 创建用户仓库
func NewUserRepository(db *sql.DB) *UserRepository {
    return &UserRepository{DB: db}
}

// 创建用户服务
func NewUserService(repo *UserRepository) *UserService {
    return &UserService{Repo: repo}
}

// 创建用户控制器
func NewUserHandler(service *UserService) *UserHandler {
    return &UserHandler{Service: service}
}
```

你会发现一个特点：

每个函数只管创建自己需要的对象，需要什么就通过参数传进来。

例如：

```
func NewUserService(repo *UserRepository) *UserService
```

意思就是：

创建 UserService 需要一个 UserRepository。

Wire 就是通过这些函数的参数和返回值，分析出整个项目的依赖关系。

### 2. Injector：告诉 Wire 最终要什么

新建 `wire.go`：

```
//go:build wireinject
// +build wireinject

package main

import "github.com/google/wire"

func InitializeUserHandler() (*UserHandler, error) {
    wire.Build(
        NewDB,
        NewUserRepository,
        NewUserService,
        NewUserHandler,
    )

    return nil, nil
}
```

这里的重点是：

```
wire.Build(
    NewDB,
    NewUserRepository,
    NewUserService,
    NewUserHandler,
)
```

你只需要告诉 Wire：

我有这些创建对象的方法，最终我要得到一个 `UserHandler`。

Wire 会自动分析：

1. UserHandler 需要 UserService。
2. UserService 需要 UserRepository。
3. UserRepository 需要 DB。
4. DB 不需要其他对象。

于是它就知道应该按照什么顺序创建。

### 3. 自动生成 wire_gen.go

安装 Wire：

```
go install github.com/google/wire/cmd/wire@latest
```

确认命令可以使用：

```
wire help
```

进入 `wire.go` 所在目录，执行：

```
wire
```

Wire 就会生成 `wire_gen.go`。

生成的核心代码大概是这样的：

```
// Code generated by Wire. DO NOT EDIT.

func InitializeUserHandler() (*UserHandler, error) {
    db, err := NewDB()
    if err != nil {
        return nil, err
    }

    userRepository := NewUserRepository(db)

    userService := NewUserService(userRepository)

    userHandler := NewUserHandler(userService)

    return userHandler, nil
}
```

你看到了吧？

Wire 实际上就是帮你自动编写了原本需要手动编写的对象创建代码。

而且生成的就是普通 Go 代码，不需要程序运行时再去解析依赖，也不依赖反射。

这是它非常重要的特点。

### 4. 最后怎么使用？

你的 `main.go` 就非常简单：

```
func main() {
    handler, err := InitializeUserHandler()
    if err != nil {
        log.Fatal(err)
    }

    _ = handler

    // 启动 HTTP 服务
}
```

以后你增加一个对象，或者修改某个对象的依赖关系，只要修改 Provider 和 Injector，再执行一次：

```
wire
```

就可以重新生成依赖组装代码。

## 三、为什么要这样设计？有什么好处？

这里是 Wire 真正有价值的地方。

### 好处 1：不需要手动管理复杂的依赖关系

假设项目有：

- 5 个数据库连接。
- 10 个 Repository。
- 20 个 Service。
- 30 个 Handler。
- Redis、Kafka、Elasticsearch。
- 配置管理、日志管理、权限管理。

如果全部手动初始化，main 函数可能越来越庞大。

Wire 可以把这些对象的组装逻辑分散到各个 Provider Set 中，最后由 Injector 统一组装。

### 好处 2：依赖关系非常清晰

例如：

```
func NewOrderService(
    repo *OrderRepository,
    redis *redis.Client,
    logger *zap.Logger,
) *OrderService
```

看函数参数就知道 OrderService 依赖什么。

不需要到处寻找全局变量，也不需要通过某个容器的字符串名称查找对象。

### 好处 3：编译阶段就能发现依赖错误

例如你写了：

```
func NewUserService(
    repo *UserRepository,
    cache *RedisCache,
) *UserService
```

但你没有提供 RedisCache 的创建方法。

Wire 生成代码时就会告诉你缺少对应的 Provider。

而不是等程序运行到某个业务逻辑时才发现问题。

### 好处 4：方便单元测试

例如：

```
func NewUserService(repo UserRepositoryInterface) *UserService
```

正式环境可以传入 MySQL 实现，测试环境可以传入 Mock 实现。

这样业务逻辑不需要直接依赖真实数据库。

### 好处 5：没有额外的运行时负担

和部分运行时依赖注入框架不同，Wire 在开发阶段生成代码。

最终运行时执行的就是普通 Go 函数调用。

因此没有依赖查找、反射解析等额外开销。

## 四、稍微进阶：Provider Set（对象分组）

当项目越来越大，你不可能把所有创建对象的函数都写在一个 `wire.Build()` 里面。

Wire 提供了 `wire.NewSet()`，可以把相关对象分组。

例如：

数据库模块：database/wire.go

```
var DBSet = wire.NewSet(
    NewDB,
)
```

用户模块：user/wire.go

```
var UserSet = wire.NewSet(
    NewUserRepository,
    NewUserService,
    NewUserHandler,
)
```

最终组装：wire.go

```
func InitializeUserHandler() (*UserHandler, error) {
    wire.Build(
        database.DBSet,
        user.UserSet,
    )

    return nil, nil
}
```

这样有什么好处？

你可以把整个项目划分为不同模块：

整个项目的依赖组装结构

Application Injector

最终组装入口

DatabaseSet

MySQL / PostgreSQL

CacheSet

Redis

UserSet

用户模块

OrderSet

订单模块

wire_gen.go

自动生成完整初始化代码

注意：上面是结构示意。实际使用时，Provider Set 应根据对象的依赖关系组织，不能简单地把模块名当成依赖关系。

## 五、Wire 常用功能记住这几个就够了

| 功能                   | 用途                        |
| ---------------------- | --------------------------- |
| `wire.NewSet()`      | 把 Provider 分组            |
| `wire.Build()`       | 声明需要哪些 Provider       |
| `wire.Bind()`        | 将具体实现绑定到接口        |
| `wire.Value()`       | 提供固定值                  |
| `wire.Struct()`      | 自动构造结构体              |
| `wire.FieldsOf()`    | 从结构体中提取字段          |
| `wire.Bind()` + 接口 | 切换 MySQL、Mock 等具体实现 |

其中我建议你优先掌握：

1. NewSet
2. Build
3. Bind
4. Cleanup（资源清理）

特别是 Cleanup，数据库、文件、消息队列等资源创建后通常需要关闭，Wire 支持在 Provider 中返回清理函数。

## 六、实际项目应该怎么组织？

如果是一个 Go 后端项目，我建议采用下面这种目录结构：

```
my-project/
├── cmd/
│   └── server/
│       └── main.go
│
├── internal/
│   ├── bootstrap/
│   │   ├── wire.go
│   │   └── wire_gen.go
│   │
│   ├── database/
│   │   ├── mysql.go
│   │   └── wire.go
│   │
│   ├── cache/
│   │   ├── redis.go
│   │   └── wire.go
│   │
│   ├── user/
│   │   ├── repository.go
│   │   ├── service.go
│   │   ├── handler.go
│   │   └── wire.go
│   │
│   └── order/
│       ├── repository.go
│       ├── service.go
│       ├── handler.go
│       └── wire.go
│
├── go.mod
└── go.sum
```

基本原则：

- 每个模块负责创建自己的对象。
- 每个模块通过 Provider Set 暴露需要的依赖。
- bootstrap 负责把各模块组合起来。
- main.go 只负责启动应用。

这样模块之间的关系就比较清晰。

## 八、最后总结：到底要不要用 Wire？

| 项目情况             | 我的建议                   |
| -------------------- | -------------------------- |
| 小型 Go 工具         | 不需要，手动初始化即可     |
| 普通 CRUD 后端       | 可以使用，也可以手动初始化 |
| 中大型 Go 后端       | 推荐考虑                   |
| 微服务项目           | 推荐考虑                   |
| 依赖非常复杂的项目   | 比较适合                   |
| 需要大量动态创建对象 | 不一定适合                 |

我个人最推荐你理解 Wire 的这个思想：

不要让每个业务模块自己去寻找数据库、Redis、日志对象。

而是：

- 谁需要什么，就通过构造函数声明。
- 谁负责创建，就提供对应的 Provider。
- 谁负责组装，就由 Injector 统一管理。

这叫做依赖注入（Dependency Injection，DI）。

Wire 只是帮你自动完成这件事情的工具。

一句话记住：Wire 不负责写业务代码，只负责把业务代码需要的各种对象正确地创建出来、连接起来。
